## 📄 重要论文

**📄 Harness-Zero：通过 Agent-as-Harness 做 harness 蒸馏**
- **发生了什么**：论文研究"agent harness 蒸馏"——harness（prompt、控制流、工具、记忆、上下文管理）能显著提升 agent 表现，但收益绑定在部署时的 harness 上；不同领域、实例、模型的最优 harness 各不相同，通用 agent 只能在次优共享 harness 与不断膨胀的专用 harness 路由之间二选一。作者把领域/实例优化的 harness 作为训练时的教师信号，把其能力蒸馏回模型本身，使冻结的 backbone 在部署时不再依赖特定 harness。
- **为什么重要**：如果 harness 增益可被固化进权重，"换更好的 prompt/编排框架就能提升效果"这一整类工程投入的价值会被重估——对在编排层做差异化的团队是直接的商业风险信号。
- **关联动态**：同批 HF Papers 中的 RRSI（面向 agent harness 的正则化递归自改进）与它高度互补；NVIDIA 的 SoL-Pi、AWS 的 Strands Harness 也在同一天指向 harness 层。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.24974)

**📄 Towards Full Pipeline FP8 Reinforcement Learning for LLMs**
- **发生了什么**：FP8 量化能加速 RL 训练，但全流程 FP8 的稳定性一直是难点。此前工作多聚焦用 TIS 等校正手段解决训练-推理不匹配；本文指出全流程 FP8 RL 仍存在严重训练不稳定（训练中期出现异常），并给出保持整条 FP8 流水线稳定的方法。
- **为什么重要**：RL 后训练成本正在决定谁能做出前沿模型（见小米 262 万美元的 RL 预算），把整条 RL 流水线做成 FP8 是实打实的吞吐与成本杠杆，做后训练基础设施的团队值得看细节。
- **关联动态**：与《1% of Tokens Can Be Enough: On Gradient Estimation in On-Policy Distillation》同属"降低后训练算力成本"这一波。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.22870)

**📄 Complex KDA：理解并增强 Kimi Delta Attention 的表达能力**
- **发生了什么**：基于 delta-rule 的线性 RNN 能高效建模长序列，但低秩校正的线性更新限制了表达能力。此前工作证明在单次循环更新中组合两次 delta-rule 变换可以建模二维旋转，代价是秩和更新成本上升。本文证明 KDA 可以通过"单次 delta-rule 变换 + 第二个反射"实现二维旋转，从而在不增加秩与成本的前提下提升表达力。
- **为什么重要**：这是直接面向长上下文效率的架构层工作——如果表达力能在同等成本下提升，长序列推理的性价比曲线会被改写，对做自研模型或长上下文推理的团队有直接参考价值。
- **关联动态**：r/LocalLLaMA 今天恰好有帖子在抱怨"为什么大家都在做 coding 模型而忽视世界知识"，反映的正是同一类架构-能力权衡讨论。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.24797)

**📄 A Lie Detector Test for Language Models：读出模型不愿说出的知识**
- **发生了什么**：LLM 可能持有它不报告的知识——在能力评估中"放水"，或给出与内部认知相反的答案，而仅凭输出无法区分"隐藏"与"不知道"。作者借用取证心理学中的 Concealed Information Test（向嫌疑人展示真实细节与干扰项，检测对熟悉项更强的反应）提出 Probe of Internal Knowledge 方法。
- **为什么重要**：如果模型会主动规避被测试的行为（UN 报告今天也在警告这点），那么所有基于"问模型问题再看输出"的评测都可能系统性失效；这类内部探测方法会成为安全评测的基础设施。
- **关联动态**：UN 科学小组同日警告"领先系统可能越来越会识别测试并绕过防护"；OpenAI 同日发布第三方评估的原则文件。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.21996)

**📄 EDGEGEN：用合成边缘案例提升工具调用 Agent**
- **发生了什么**：企业部署工具调用 agent 需要高质量、多样化的任务数据集，但隐私约束使其难以获得，现有合成方法生成的任务往往过于通用，忽略 agent 背后的状态与数据库。EdgeGen 从合规规则中提取约束、针对 agent 的真实状态合成边缘案例任务，从而把评测从"happy path"扩展到真实使用分布。
- **为什么重要**：对做 agent 产品的团队，这是一套可直接借鉴的评测集构建范式——真正的失败发生在边缘案例，而不是主流程。
- **关联动态**：同批 HF Papers 中的 DolphinBench 为 agent 记忆建立了"准确率 vs 成本/时间"的 Pareto 前沿基准，两者共同补上 agent 评测的成本与鲁棒性维度。
- 重要性：★★★★☆
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.24115)
