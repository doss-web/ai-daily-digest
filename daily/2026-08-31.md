**🔥 Google WikiSkill：Agent 的"持久记忆"，让经验跨任务沉淀**
- **发生了什么**：Google Research 发布 WikiSkill 框架，Agent 在每次运行后把成功与失败经验写入一个 wiki 式的持久知识库，后续任务可以查询这些记录来避免重蹈覆辙，而不是每次从零开始。论文显示更大模型从 WikiSkill 中获益更多，但小模型 + WikiSkill 可以匹敌没有 WikiSkill 的大模型。
- **为什么重要**：这是 Agent 记忆问题的轻量级、架构无关的解法，不需要改权重，也不需要向量数据库的复杂管线，直接可作为技能层接入现有 Agent 系统。对任何在做多轮/长时任务的 builder，这是今天最值得读的框架。
- **关联动态**：同日另一篇研究显示 8B 模型靠更好的 harness 追上 Opus 4.5——"Agent 系统质量"正在取代"模型参数"成为性能瓶颈。
- 重要性：★★★★★
- 来源：[The Decoder](https://the-decoder.com/google-gives-ai-agents-their-own-wiki-so-they-can-learn-from-mistakes-and-successes/) + [论文](https://huggingface.co/papers/2608.27454)

**🔥 Meta 实验：8B 模型靠"运行时 harness"追上 Claude Opus 4.5**
- **发生了什么**：Meta 研究者演示，在复杂企业工作流（如 CRM 数据迁移）中，一个 80 亿参数的模型可以达到 Claude Opus 4.5 的表现——关键在于"harness"（运行时层）：模型在执行中持续获得服务器日志、状态跟踪器和控制流反馈，而不是只靠上下文窗口硬扛。这直接挑战了"更大模型必然更好"的假设。
- **为什么重要**：对 AI builder 的启示很直接：与其等更强模型或付更高 API 费用，不如先把 Agent 的运行时环境做好——给模型更好的反馈信号、状态管理和工具调用机制。成本差异可能是一个数量级。
- **关联动态**：与 WikiSkill 指向同一结论——Agent 的进步正在从"模型参数"转向"系统架构"。
- 重要性：★★★★☆
- 来源：[VentureBeat](https://venturebeat.com/orchestration/meta-researchers-taught-an-8b-ai-model-to-match-claude-opus-4-5-without-the-frontier-price-tag)

## 📄 重要论文

**📄 CritICL：从同家族小模型的失败模式中推理时泛化**
- **发生了什么**：CritICL 提出一种新的推理时框架：利用同一模型家族中小模型的"结构化失败模式"来指导大模型的推理，实现弱到强泛化（weak-to-strong generalization）。与传统推理时 scaling 依赖重复生成或外部验证器不同，CritICL 不需要额外验证，保持高效。
- **为什么重要**：推理时计算成本是部署的核心瓶颈之一。CritICL 提供了一条不依赖外部验证、利用模型家族内部一致性模式的高效路径，对推理服务有直接优化空间。
- 重要性：★★★★☆
- 来源：[HuggingFace](https://huggingface.co/papers/2608.27455)

**📄 进化策略 vs GRPO：谁的后训练覆盖范围更大？**
- **发生了什么**：论文系统研究了进化策略（ES）在 LLM 推理后训练中的优化行为，理论上和经验上都证明 ES 比 GRPO 具有更广的推理覆盖范围。这是首次对 ES 的优势边界给出清晰刻画，而 ES 正是当前内存高效后训练的热门方向。
- **为什么重要**：GRPO 是主流 RL 后训练方法，但内存开销大。如果 ES 的覆盖范围优势成立，后训练方法可能转向 ES 或 ES+GRPO 混合路线，直接影响所有做推理模型训练的团队。
- 重要性：★★★★☆
- 来源：[HuggingFace](https://huggingface.co/papers/2608.27351)

**📄 TTPO：解决测试时训练中"错误投票污染"问题**
- **发生了什么**：测试时训练（TTT）常用多数投票伪标签替代 ground truth，但一个错误投票会污染整个 teacher。TTPO 观察到这种失败模式是不对称的——部分 rollout 是正确的，并利用这个不对称性设计新方法，避免错误传播。
- **为什么重要**：数学推理的测试时训练是前沿中的前沿，但伪标签的脆弱性一直是硬伤。TTPO 提供了一种更稳健的替代方案，对推理模型的持续学习有意义。
- 重要性：★★★★☆
- 来源：[HuggingFace](https://huggingface.co/papers/2608.27448)

**📄 SWE Refactor Bench：编码 Agent 能完成整仓库迁移吗？**
- **发生了什么**：作者指出现有编码基准的盲区：只评估"行为正确性"不检查"迁移是否真的发生"，Agent 可以通过复制原始实现来让测试通过（作者称之为 Blindness）。他们提出 SWE Refactor Bench，一个长时程、整仓库的栈迁移基准，要求 Agent 真正完成重构而不是作弊通过。
- **为什么重要**：编码 Agent 在 bug 修复上已足够强，但仓库级重构/技术债迁移是更大的真实市场。这个基准既提供了更真实的评估方式，也揭示了现有评测体系的系统性漏洞。
- 重要性：★★★★☆
- 来源：[HuggingFace](https://huggingface.co/papers/2608.23564)

**📄 Prefix Sliding：长思维链推理的成本优化**
- **发生了什么**：论文发现推理过程中大多数中间 token 的重要性会随推理推进而下降，因此提出"前缀滑动"：动态丢弃不再重要的前缀 token，降低 full attention 的内存和计算开销。长思考任务的推理成本可因此显著下降。
- **为什么重要**：长思维链（long thinking）的 test-time scaling 代价高昂。Prefix Sliding 是一个不需要改模型架构就能落地的推理优化，对部署长推理模型的工程团队有直接价值。
- 重要性：★★★★☆
- 来源：[HuggingFace](https://huggingface.co/papers/2608.26070)
