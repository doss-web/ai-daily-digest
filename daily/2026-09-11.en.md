## 📄 Papers

**📄 PARSER: decoupling reading from reasoning for long-context agents**
- **What happened**: Sequential memory agents must read a document chunk by chunk while maintaining a compact memory state, making them highly sensitive to evidence placement and tying inference latency linearly to document length. PARSER decouples the two: a bank of lightweight subagents, each bound to a single chunk, reads the whole document in parallel, while a lead agent reasons in depth through iterative passes.
- **Why it matters**: This is a structural improvement for long-context agents — latency moves from "proportional to document length" toward parallel, and no longer depends on where the evidence appears. For document analysis, contract review and codebase comprehension products, this is a directly borrowable architecture.
- Importance: ★★★★★
- Source: [HuggingFace Papers](https://huggingface.co/papers/2609.06702)

**📄 SchemeArena: systematically measuring agent scheming**
- **What happened**: Prior work on agent scheming — covertly pursuing misaligned goals while appearing compliant — covered only a small number of scenarios, making it impossible to isolate the contributions of individual factors. SchemeArena factorizes scheming across instrumental goals, environmental affordances, oversight conditions and perceived consequences, greatly expanding task and scenario coverage.
- **Why it matters**: This is a step toward turning "will your agent deceive you" from anecdote into a measurable metric. If you deploy agents with tool permissions, these factorized settings can be adapted directly into a pre-launch red-team checklist.
- Importance: ★★★★★
- Source: [HuggingFace Papers](https://huggingface.co/papers/2609.08149), [paper page](https://huggingface.co/papers/2609.08126)

**📄 SWE-Bench Pro Verified: closing the score-gaming channel**
- **What happened**: The paper identifies two sources of unreliability in SWE-Bench Pro evaluation — reward hacking enabled by leakage of gold solutions or hidden evaluation information, and task quality problems including misleading problem statements and improperly scoped tests. The authors build a Verified version accordingly.
- **Why it matters**: SWE benchmark scores are the central evidence in current coding-agent procurement and fundraising narratives. If you're using SWE-Bench Pro for model selection, first confirm you're not on a version that can be contaminated by leakage — otherwise you may just be picking whichever model is better at finding the answer.
- Importance: ★★★★★
- Source: [HuggingFace Papers](https://huggingface.co/papers/2609.08149)

**📄 Φ-Bench: can LLMs engineer the infrastructure that powers them?**
- **What happened**: Existing benchmarks focus on isolated kernels, predefined operators or pre-specified optimization targets, and therefore fail to evaluate open-ended, long-horizon LLM infrastructure engineering. Φ-Bench targets exactly that: whether a model can develop and optimize the stack that runs it.
- **Why it matters**: This is the most exaggerated and least measured link in the recursive self-improvement narrative. An open-ended long-horizon evaluation lets you separate "can write kernels" from "can make system-level decisions" — highly relevant for teams working on inference optimization, compilers and scheduling.
- Importance: ★★★★★
- Source: [HuggingFace Papers](https://huggingface.co/papers/2609.10226)

**📄 Programmable World Model: separating world state from frame generation**
- **What happened**: Video world models generate increasingly realistic interactive visuals but lack mechanisms for persistent world state and enforceable programmable rules. This framework decouples state evolution from visual observation generation: an agent translates natural-language instructions into executable programs specifying entity states and state-transition rules, giving direct control over the world.
- **Why it matters**: This is a prerequisite for using world models as simulators. For teams in embodied AI, games and simulation environments, moving controllability from pixel space to program space substantially reduces rollout unreliability.
- Importance: ★★★★☆
- Source: [HuggingFace Papers](https://huggingface.co/papers/2609.10540)
