**🔥 OpenAI 一次性发布 700+ 份 AI 生成数学手稿，数学界呼吁抵制**
- **发生了什么**：OpenAI 一口气放出 722 份 AI 生成的数学手稿（36Kr 统计），据称绝大多数结果来自同一套流程、同一个内部模型；次日因一处符号错误撤回三篇。数学界反应激烈：Association for Human Mathematics 发起抵制呼吁，Fields 奖得主 Terence Tao 公开警告 AI 对开放问题的"批量收割"会让某些数学分支变得贫瘠。TechCrunch 指出，这批证明偏离了 OpenAI 自己咨询的数学家小组所定的规范。
- **为什么重要**：当生成证明的边际成本趋近于零，瓶颈立刻转移到验证、评审与信誉机制——这正是 AI 研究自身即将遭遇的同一问题。如果你的产品依赖模型输出"看起来对"的产物（代码、报告、分析），今天数学界的反应就是三个月后你所在领域的反应。后续值得盯：OpenAI 是否公开验证协议与错误率数据。
- **关联动态**：InfoQ 刊出的 o1 奠基人观点称"1 万个 Agent 解出世界级难题，多 Agent 贡献不到 10%"——与"同一内部模型、同一流程"的工业化产出互相印证；同日 arXiv 上的 TRACE 论文提出验证器脆弱性诊断，是这条新闻的技术对偶面。

**🔥 Google 把 Gemini 变成企业级通用 Agent，并给它配了邮箱**
- **发生了什么**：在 Gemini at Work 活动上，Google 发布面向企业的"通用"Gemini Agent，运行于 Gemini Enterprise 应用内，可在后台跨应用与设备规划并执行任务，能把工作委派给子 Agent、调用多个模型；它还会获得自己的工作身份，包括一个邮箱地址。国内媒体用"缝合怪"形容其支持调用 Claude 等第三方模型。
- **为什么重要**：给 Agent 分配邮箱与身份，意味着 Agent 从"功能"变成组织里的"成员"——权限、审计、计费、撤销凭证都要按"入职/离职"来设计。做内部工具与系统集成的团队，需要开始考虑 Agent 可发现、可寻址、可授权的接入方式，而不是只暴露给人用的界面。
- **关联动态**：Haiku 5.5 把 computer use 的成本压到 $0.10/百万输入 token，正好是这种"多模型路由"架构里最合适的廉价执行体；OpenAI 的 Dots 与 Meta 的 Muse 则在消费侧抢同一个 Agent 入口。
