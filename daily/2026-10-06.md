- 重要性：★★★★★
- 来源：[Diff (Wikimedia Foundation)](https://diff.wikimedia.org/2026/10/05/openai-rogue-agent-activities-found-on-wikimedia-projects/) / [The Verge](https://www.theverge.com/news/1004929/wikipedia-openai-rogue-bots-wikimedia-foundation-outage)

**🔥 Reflection 发布 Beam：501B 开源权重 MoE，主打"低算力对标中国模型"**
- **发生了什么**：Reflection AI 发布其首个开放权重模型 Beam，501B 稀疏 Mixture-of-Experts、每 token 激活 23B 参数，面向 coding 与 agentic 负载。官方称其在推理任务上与 GLM-5.2 持平，但推理算力消耗只有后者的 1/3 到 1/4，Apache 2.0 权重计划在 2026 年 10 月晚些时候发布。商业模式不是卖 API，而是向企业和主权国家出售"AI 工厂"——用客户私有数据训练定制模型。
- **为什么重要**：这是第一家把"西方开源权重"当作竞争叙事核心的美国前沿实验室。对 builder 而言关键是权重能否按期以 Apache 2.0 落地——501B/23B 激活的规格意味着用有限的 H200 就能跑出接近前沿的 agent 能力。
- **关联动态**：同日 Aleph Alpha 发布 Kolibri，欧洲也在用开源权重打"主权 AI"牌；开源权重正在从"中国实验室的标签"变成全球性的地缘产品。

**🔥 OpenAI 在欧盟给 ChatGPT 和 Codex 输出加水印，全球 API 用户可退出**

**🔥 MCP 的 agent-to-agent 通信被发现有结构性信任缺口**
- **发生了什么**：Ars Technica 报道，Google 等厂商的 agent 实现中存在的漏洞，暴露了 MCP 协议在 agent 间通信上的结构性问题——恶意 prompt 可以沿着信任缺口从一个 agent 传播到另一个 agent。

- **关联动态**：与 Wikimedia 的 OpenAI agent 事件叠加，本周的真正主题是"agent 权限与信任边界"。

## 📄 重要论文

**📄 WEFT：工具使用后训练的瓶颈不在环境合成，而在整个 agent 交互系统**
- **发生了什么**：论文指出，当前工具使用后训练的扩展工作主要集中在"合成可执行环境"，但环境只是"环境 + 任务 + agent harness + evaluator"这套交互系统中的一环。孤立地扩展环境并不能保证模型能力同步提升，因为可靠的学习信号依赖于所有组件的协同一致。
- **为什么重要**：这是对"合成更多环境就能提升 agent 能力"这一默认假设的直接反驳。如果你在搭 agent 训练管线，应该把 evaluator 和 harness 当作一等公民与模型一起迭代，而不是只堆环境数量。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.36887)

**📄 CUAWright：用约 3000 行 bash 统一 computer-use agent 的接口**
- **发生了什么**：现有 computer-use agent 通常把模型与领域专属 harness 绑死，工具在任务执行前就已固定，GUI 原生 + 静态 harness 限制了模型直接以程序方式操作系统状态、也无法灵活构造工具。CUAWright 提出一个约 3000 行代码的最小终端 harness，让 agent 用 bash 命令直接操作，并动态构造工具。
- **为什么重要**：这是"agent 用代码操作电脑"路线的一个极简开源参考实现。随着模型编码能力提升，静态 GUI harness 正在成为瓶颈——做 desktop agent 的团队可以直接借鉴这个架构取舍。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.04116)

**📄 The Extender：给 Transformer 加一条"拼接通道"**
- **发生了什么**：标准 Transformer 中各层只通过残差流 h（一个叠加通道）与后续层通信。The Extender 增加了一条拼接通道 x：每层同时输出残差更新 δ 加进 h，以及一个更小的扩展 ε 追加进 x；FFN 和 query 读取 h，但 attention 的 K/V 投影只以 x 为输入。
- **为什么重要**：这是一个结构上非常干净的改动，直接针对残差流的"叠加干扰"问题——注意力读到的历史被所有层的更新混合在一起。如果它在长上下文或深层模型上稳定成立，就是一个低成本、可迁移的架构改进。
- 重要性：★★★★☆
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.32759)

**📄 QuantWM：让视频世界模型的 2-bit KV cache 保持时序一致**
- **发生了什么**：视频世界模型依赖 KV cache 维持长期时序一致性，但 cache 随生成增长成为部署瓶颈。现有的 2-bit 量化方法在 VBench 上近乎无损，但用于视频世界模型时仍会造成严重的时序闪烁与画面退化；论文进一步发现 Key 的量化是主要问题。QuantWM 提出一种时序一致的 2-bit KV cache 量化方案。
- **为什么重要**：视频生成与世界模型的推理成本几乎全部压在 KV cache 上。"量化后仍保持时序一致"直接决定了长视频生成或交互式世界模型能否把成本压到可商业化的水平。
- 重要性：★★★★★
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2609.26425)

**📄 Queen：4B 参数的国际象棋模型，能解释自己的棋**
- **发生了什么**：现代引擎是"沉默的专家"——棋力超人类但不给解释；语言模型则相反，能说会道但棋力不济。Queen 是一个 4B 参数的棋类语言模型，在国际象棋上达到典型特级大师水平，同时能解释自己的走法和计划，方法上通过互补式训练实现领域推理。
- **为什么重要**：这是"专家级能力 + 自然语言解释"在同一模型上同时成立的少见案例。对做垂直领域 reasoning 产品的团队而言，它提供了一个关于"如何让小模型既强又可解释"的方法范式。
- 重要性：★★★★☆
- 来源：[HuggingFace Papers](https://huggingface.co/papers/2610.03695)
