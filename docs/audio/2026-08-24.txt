重要论文。
发生了什么。现有 agent 技能库通常离线构建，agent 在推理中新发现的有效工作流（workflow）执行完就被丢弃。FlowEvo 提出一个无需训练的框架：把成功的工作流编译成可调用的技能入库，技能反过来指导新工作流的生成，从而在推理时形成"工作流↔技能"的共同进化闭环。
为什么重要。这与今天 GitHub 上 skills 类项目（mattpocock/skills、book-to-skill 等）的集体爆发是同一趋势的学术表达：把一次性经验沉淀为可复用资产，是 agent 从"能跑通"走向"越用越强"的关键机制。
发生了什么。研究者将三个前沿 MoE 模型（Alibaba、OpenAI、NVIDIA，各 3.6-4.0B 激活参数）微调到用希腊语思考。在准确率 benchmark 上几乎什么都没发生——并且只换随机种子就能让分数波动 7.7 分，比所有数据与配方效应都大。真正的变化存在于准确率看不到的地方：基础模型从不主动用希腊语思考（1000 次推理中 0 次），SFT 与 RL 对思维轨迹的影响方式也不同。
为什么重要。这是对"以 benchmark 数字选模型"的方法论警告。当模型能力足够强时，准确率对训练配方的变化极不敏感，需要检查推理轨迹本身。对做多语言应用的团队，这个结论直接关系到"思考语言"的设计取舍。
发生了什么。长上下文 LLM 的 prefill 阶段是注意力平方复杂度的主要瓶颈。FlashPrefill V2 在 v1 的瞬时模式发现与动态阈值基础上，加入了生产部署所需的块稀疏实现，目标是把长上下文 prefill 的算力成本降一个量级。
为什么重要。prefill 优化直接降低 TTFT 和长上下文场景的推理成本。对做长文档处理、agent 记忆、RAG 服务的团队，这是值得密切跟踪的方向——如果落地到开源推理栈，能直接省预算。
发生了什么。LLM coding agent 通过接口向终端发送 Bash 命令，而这些接口可能对模型输出做序列化、包装、重新解析。只靠"匹配的执行分数"无法区分模型生成错误和接口传输引入的错误。QuoteBench 用 14 个事故源家族的 56 个 one-shot 任务，交叉"生成契约 × 执行传输"，给出了量化这一边界的方法论。
为什么重要。agent 调试中最难的问题之一是"模型是对的，但环境/传输层坏了"。QuoteBench 提供了一套精确定位错误来源的手段，对构建 agent 工具链的开发者有实际参考价值。
开源项目。
发生了什么。OpenAI 的轻量终端 coding agent，今日新增 2,729 star，是当天 GitHub Trending 增长最快的项目之一。
为什么重要。终端 coding agent 已是开发者日常基础设施。关注 codex 的迭代可以直接了解 OpenAI 对 agent 工作流的官方实践，包括工具调用、会话模型和终端 UX 的最新设计。
发生了什么。TypeScript 教育家 Matt Pocock 开源了自己的 .agents 目录——一套他在真实工程中打磨的 Claude Code / Codex skills，今日 +2,448 star。
为什么重要。这是"真实工程师的 skills"而非玩具示例。可以直接复制到自己的 agent 配置里试用，也可以参照它的结构来组织自己的 skills。代表"skill 工程"正成为 agent 时代开发者的新基本功。
关联动态。VoltAgent/awesome-agent-skills（1000+ skills 合集）同日在榜，skill 生态正在快速成型。

为什么重要。Nous 在开源社区的号召力意味着这个项目有持续迭代的潜力。对开发者来说，值得关注它在记忆、自进化机制上的设计——这可能是"越用越懂你"的 agent 架构的开放实现。
