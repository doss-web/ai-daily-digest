关联动态。与 Haiku 5.5 的降价形成双向挤压——模型变便宜与本地算力变强同时发生，中间层（纯 API 转售、薄封装 SaaS）最难受。
发生了什么。新 Decisions API 对文本与图像的分类速度约为 Responses API 的 10 倍，返回 yes/no 概率、类别选择或量表评分，定价 $0.10 每百万输入 token，输出不计费。同日 OpenAI 将付费 API 层级从 5 档精简为 3 档。Simon Willison 已用 GPT-6 Astra 读文档生成了 llm-openai-decisions 插件，相比同类 Jev 多出图像输入能力。
为什么重要。把"决策"从生成式调用中剥离成独立、廉价、可缓存的 API 原语，直接改变 agent 里 router / classifier / guardrail 的写法——过去这些要么靠 prompt 硬凑，要么自训小模型。
关联动态。Liquid AI 同日发布 d1-3B 与 d1-omni-600M 决策模型，单次前向返回类型化答案、零输出 token——"决策模型"这一品类一天内被三家同时押注。
发生了什么。EmbeddingGemma 2 是 740M 参数开放权重多模态嵌入模型（Apache 2.0），基于 Gemma 4，把文本、图像、视频、音频、代码映射到同一个 768 维空间，官方称性能超过两倍大小的竞品，量化后约 191MB 内存即可端侧运行。配套地，Google 的 SynthID 水印检测器对公众开放，已有 1800 亿条内容带水印，但只能识别 SynthID 体系内内容。
为什么重要。端侧 + 跨模态 + 单向量空间，三个条件凑齐意味着本地 RAG 与本地以图搜图不再需要任何服务端。配合 Gemma 4 一类小模型可以做到完全离线的 RAG 应用。SynthID 检测器公开则是内容溯源目前唯一可执行、但覆盖面有限的工具。
关联动态。r/LocalLLaMA 上已有人把 EmbeddingGemma 2 的文本与视觉塔移植到 WebGPU 推理库 ruNNtime，实现浏览器内 GPU 搜图。
发生了什么。Hermes Agent 的开发商 Nous Research 完成 $90M B 轮，确认 $1.5B 估值，同时发布面向商业用户的 agent 产品。
为什么重要。开源权重阵营的明星团队开始向企业级 agent 变现，说明"开源做品牌、闭源 agent 收钱"正在成为标准路径。对独立开发者，这是又一条被验证过的商业化路线。
关联动态。与 Meta/Microsoft 限制 Claude 形成对照——企业 agent 市场的竞争焦点正从"用哪家模型"转向"谁来托管工作流"，而这恰好是模型厂商的软肋。
重要论文。
做了什么。作者提出 WebFovea，一个基于视觉的 web agent，在 WebRetriever Challenge 2026 的协议 III 上拿到 57.0/100 的最终分，位列第二。论文的核心论断是：一个强的多模态 LLM 对这类任务是必要的但不充分——模型的决策要穿过浏览器这一层才能落地，"点击落点"才是真正的瓶颈。
为什么重要。所有做 browser-use / computer-use agent 的团队都卡在同一个地方：规划对了、执行坐标偏了。这篇给出的是可量化的端到端评测口径，而不是又一份能力吹捧。
做了什么。论文系统研究了 agentic 后训练与 MoE 专家选择之间的联系。观察结果很具体：现成 MoE 模型中的专家路由本身就呈现出与 agent 轨迹对齐的专门化结构——在 agent 相邻轮次之间，专家路由的重叠度明显更高。
为什么重要。如果你的 agent 跑在稀疏模型上，这条结论意味着 MoE 的路由结构可以被 agentic RL 直接利用甚至"塑形"，而不是当成黑盒。对做推理成本优化的团队，这是把稀疏性从"省算力"变成"对齐行为"的杠杆。
做了什么。TimeBraid 通过交错的全局残差注意力层，把预训练语言模型与预训练时间序列基础模型对齐。结果是一组模型同时继承了语言侧的指令跟随与推理能力，以及时序侧的连续信号感知与零样本预测能力，两个模态在同一个空间里被理解与生成。
为什么重要。时序预测长期被困在专用模型的孤岛里，无法获得 LLM 的推理与工具调用能力。这类"对齐两个预训练模型"而非"从头训练多模态"的路线，对算力有限的团队更可复制。
做了什么。现有传感器模型基本止步于感知——识别状态或预测结果，动作则被拆到独立的、往往是封闭标签空间的任务模型里。作者提出 SLA（Sensor-Language-Action）框架，用语言作为传感器观测与动作之间的语义接口，在单一模型中统一三者。
为什么重要。这是把"感知—决策"的缝合线去掉的一次尝试。对做具身智能或工业 IoT 的团队，语言作为接口意味着新增传感器或新增动作时不必重训整个模型，扩展成本结构发生变化。
做了什么。LLM agent 在新环境里缺乏操作知识，必须自己摸索工具行为与环境约定；没有对过往尝试的记忆，它们会在不同任务里重复同样的错误，导致失败率更高、轨迹更长。现有做法要么依赖人写的指南，要么依赖训练任务 + oracle verifier 构建程序性记忆——两者都要求事先了解环境。DAEDALUS 用自生成任务来引导这一过程。
为什么重要。如果 agent 能在没有人类指南、没有 oracle 的环境里自己长出记忆，那么"部署到新环境"的前置成本会大幅下降。对做企业级 agent 交付的团队，这直接对应实施周期。
开源项目。

为什么重要。逆向工程是 agent 能力落地最直接的高价值场景之一——目标明确、反馈可验证、不需要人工标注。对安全团队和做兼容层/互操作的开源项目，这是可立即上手的工具链。
是什么。捕获 agent 在会话中做的一切，用 AI 压缩，再把相关上下文注入未来会话。支持 Claude Code、OpenClaw、Codex、Gemini、Hermes、Copilot、OpenCode 等。今日 +578 star。
为什么重要。上下文丢失是所有长周期 agent 工作流的头号痛点，而各家官方 memory 方案彼此不兼容。一个跨厂商的通用层，对同时用好几个编码 agent 的开发者实用价值很高。

AI 圈热议。
在讨论什么。XDA Developers 的一篇文章在 HN 上引发讨论（39 分、16 条评论），核心论点是：一个本地运行的免费 LLM 已经能满足作者的全部需求，因此不再订阅 ChatGPT / Claude / Gemini。与之呼应的是 r/LocalLLaMA 上对 llama.cpp 新 PR 的热议——这个 PR 为常驻主机内存的 MoE 专家加了 GPU 缓存，作者直接喊话"Are you GPU Poor? Show your speedups"，即专门为显存装不下整个 MoE 的用户做提速。
为什么重要。这两条放在一起说明，本地推理的门槛正在从"能不能跑"转向"跑得够不够快"。当 EmbeddingGemma 2（191MB 内存、端侧）和 MoE 专家缓存这类优化同时出现，"订阅 vs 本地"的边界会以肉眼可见的速度右移。
关联动态。微软同一天发布 $2,599 起的 AI PC 与 $5,999 的开发机——如果本地推理真能替代订阅，这批硬件就是它的价格坐标。
在讨论什么。magicnumbers.io 的文章《AI Model Groupthink》在 HN 上引发讨论（23 分、7 条评论），指向的是模型输出趋同——不同厂商、不同架构的模型在相同问题上给出高度相似的判断。这个担忧与今天的另一条线互为印证：Simon Willison 引用的数学爱好者 Jake Boggan 说，他为一个猜想投入了数千小时、24 年，"I don't know what to think exactly"——最后它是被模型在编号 180 的问题里证出来的。
为什么重要。如果模型的"多样意见"只是同一种先验的多次采样，那么用多模型投票做评估、做合成数据、做事实核查的方法论都要重新审视。这对做 eval 和合成数据管线的团队是个直接冲击。
关联动态。OpenAI 一口气公开 372 项数学成果后，25 位菲尔兹奖得主联名质疑这是"批量生产真理"而非提出新想法——两条讨论在同一个问题上汇合：AI 产出的"正确"是否等于"有价值"。
独立开发者灵感。
灵感来源。r/LocalLLaMA 上有人发布 MacroStories——19,969 个参数、FP32 下 81KB 的模型，能维持 100 token 级别的连贯故事生成。作者给出的对照尺度很直观：比 1M 参数的 TinyStories 小约 50 倍，比 AlexNet 小约 3,000 倍。架构上是 32 维隐状态、378 词表、单个 decoder block 重复施加 4 次并共享权重。作者明确说这不是通用 LM，但在其受限的故事分布内可稳定工作。
可借鉴的点。这是极好的"能力下限"实验模板。如果你在做玩具级 AI 功能（自动生成商品短描述、游戏内台词、通知文案），这条路径说明你完全可以训练一个几万参数的模型塞进 100KB 以内，跑在浏览器或单片机上——零推理成本、零网络延迟、零隐私顾虑。
灵感来源。r/LocalLLaMA 上一位开发者把 EmbeddingGemma 2 的文本塔与视觉塔移植到了 ruNNtime——一个 TypeScript 写的 WebGPU 推理库，并做出了一个照片库 demo：搜索完全在浏览器内、在你的 GPU 上运行，用户用自然语言描述就能找到照片。EmbeddingGemma 2 把图像和文本映射到同一个 768 维空间，这是整件事能成立的前提。
可借鉴的点。端侧语义搜索现在只需要一个静态网页即可交付。任何做相册、素材库、笔记、本地文档工具的独立开发者，都可以零服务器成本地加一个"用描述找图/找文"的功能，而且可以直接拿这句话当卖点——"你的照片从不离开你的设备"。
灵感来源。r/LocalLLaMA 上热传的 llama.cpp PR 29887，为常驻主机内存的 MoE 专家加上 GPU 缓存，作者的定位非常明确——"Potentially big speedup for MoE models that don't fully fit in VRAM"，并喊话"Are you GPU Poor? Show your speedups"。
可借鉴的点。对自托管推理的独立开发者，这条几乎等于硬件降级。以前装不下整个 MoE 就等于放弃，现在可以在消费级显卡上跑更大的稀疏模型。如果你在算"要不要升级到 48GB 显存"，先等这个 PR 落地再决定。
今日观察。今天的核心矛盾是"模型变便宜"和"算力变贵"同时发生。Haiku 5.5 把输入价压到 $0.10，OpenAI 的 Decisions API 干脆对输出不计费，小型模型第一次能撑起"每步都调模型"的 agent 循环；而同一天微软发布了 $2,599 起的 AI PC 和 $5,999 的开发机，把本地推理的门槛用一个明确的价格标了出来。真正值得记下的转折是"决策模型"作为独立品类突然成型——OpenAI Decisions API、Liquid AI 的 d1-3B/d1-omni-600M、Laya 在同一天从三个方向撞上同一个抽象：把 LLM 从"生成文本"降级成"返回一个带概率的标签"。这对 agent 架构的冲击比任何一次模型升级都更直接，因为它意味着 router、guardrail、分类器不必再靠 prompt 工程硬凑，而是变成可缓存、可版本化、可比价的 API 调用。三个月后回头看，最可能被反复引用的是 Haiku 5.5 的价目表，因为它第一次给"小模型够用了"这件事标定了成本坐标；OpenAI 的 372 项数学成果声量最大，但 25 位菲尔兹奖得主联名反对，说明它带来的是学术伦理争议而非可迁移的工程能力。而被低估的一条是 Meta 与微软限制员工使用 Claude——当大厂开始把 AI 工具选型当作供应链安全问题处理，开源权重与本地部署的商业价值会被重新定价，这正好解释了为何同一天 Nous Research 能以 $1.5B 估值融到 $90M 去卖企业 agent。
